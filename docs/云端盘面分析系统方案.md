# 云端盘面分析系统方案

## 一、架构总览

```
┌─ 本地（你的电脑）─────────────────────┐
│ V15Plus                                 │
│   ├─ 板块资金流 Tab（每日收盘后跑一次） │
│   └─ 导出缓存 → POST 到云端             │
└────────────────────────────────────────┘
          ↓ JSON（板块评分/V15数据/新闻蒸馏）
          ↓ HTTP POST
┌─ 云端（腾讯云轻量服务器 99/年）────────┐
│ 数据层                                   │
│   ├─ 东方财富板块资金流（定时全量采集）  │
│   ├─ akshare 新闻（定时采集）            │
│   ├─ news_distiller 蒸馏（定时运行）     │
│   └─ V15Plus 缓存（接收本地 POST）      │
│                                          │
│ 调度层（crontab）                        │
│   09:40 → 开盘采集 + 推送                │
│   11:30 → 午间采集 + 推送                │
│   13:25 → 下午采集 + 推送                │
│   14:30 → 尾盘采集 + 推送                │
│   15:02 → 收盘采集 + 推送                │
│                                          │
│ 服务层                                   │
│   ├─ DeepSeek API 调用 → 生成报告        │
│   ├─ 企业微信机器人（主动推送）          │
│   └─ 简单 HTTP 服务（按需查询板块）      │
└────────────────────────────────────────┘
          ↓ 企业微信消息推送
          ↓ 按需查询响应
┌─ 你的手机──────────────────────────────┐
│ 企业微信群                               │
│   ├─ 定时收到 5 次推送                   │

```

## 二、存储需求评估

| 数据类型 | 每次大小 | 每日（5次） | 年度（250天） |
|---------|---------|------------|-------------|
| 板块资金流（128板块×15字段） | ~80KB | ~400KB | ~100MB |
| V15Plus 缓存 | ~30KB | ~30KB（1次） | ~7.5MB |
| 新闻蒸馏结果 | ~20KB | ~100KB | ~25MB |
| DeepSeek 报告（推送记录） | ~5KB | ~25KB | ~6MB |
| **合计** | **~135KB** | **~555KB** | **~140MB** |

腾讯云轻量 99/年 标配 50GB，**10 年用不到 5%。存储无压力。**

## 三、定时任务时间表

| 时间 | 定位 | 数据采集 | 推送内容 |
|------|------|---------|---------|
| **09:45** | 开盘定位 | 板块资金流 + 新闻 + V15缓存 | 今日基调、与昨日衔接、开盘核心变量 |
| **11:35** | 午间复盘 | 同上（刷新） | 上午回顾、下午方向预判 |
| **13:30** | 下午确认 | 同上（刷新） | 上午结论是否兑现、下午走势修正 |
| **14:35** | 尾盘预判 | 同上（刷新） | 尾盘方向、明日预期 |
| **15:05** | 收盘复盘 | 同上（刷新） | 今日总结、明日策略 |

每次执行步骤：
```
1. 采集东方财富板块资金流（全量 128 板块）
2. 采集 akshare 新闻
3. 运行 news_distiller 蒸馏新闻
4. 读取 V15Plus 本地缓存（本地 POST 上来的）
5. 合并全量数据 → 调 DeepSeek
6. 推送到企业微信群
```

## 五、Prompt 终稿

### 5.1 系统角色与数据纪律

```
你是一位 A 股盘面分析师。你的输入是全量实时市场数据 + 本地量化评分 + 新闻蒸馏结果。
你的输出是一份结构化的盘面解读报告，核心指向一个判断：
当前市场处于什么阶段，接下来最可能怎么走。
```

**时间感知：**
当前日期时间由输入数据提供。LLM 根据"市场状态"字段自行调整分析侧重：
- 开盘阶段 → 今日定位、与昨日的衔接
- 上午盘中/午间 → 上午回顾、下午预判
- 下午盘中/尾盘 → 当日总结、明日预期
- 收盘 → 全面复盘、明日策略

**数据来源标签（硬性约束）：**

| 标签 | 含义 |
|------|------|
| 【实时】 | 今日东方财富实时采集的板块资金流数据 |
| 【V15】 | V15Plus 本地量化系统评分 |
| 【新闻】 | 新闻蒸馏产出的结构化结果 |
| 【趋势】 | 当日多时间点对比的趋势变化 |
| 【外部】 | 美股/港股/汇率等外部参考 |
| 【推演】 | 基于上述数据的逻辑推导 |

纪律要求：
1. 每条数据引用必须标注来源标签
2. 缺失数据如实写"暂无数据"，不得编造
3. 推断必须标注置信度（高/中/低）+ 推断依据
4. 时间表述以输入中的当前日期为基准

### 5.2 输入数据格式

```yaml
# 大盘指数（5个）
indices:
  - name: 上证指数
    price: 4075.31
    change_pct: -0.90
    amount: 10185    # 成交额(亿)

    super_large: -12.5    # 超大单
    large: -20.1          # 大单
    medium: 8.3           # 中单
    small: 5.2            # 小单

# V15Plus 评分

  - sector: 半导体

    power_score: 72       # 板块动力分

    percentile: 80        # 分位

# 新闻蒸馏结果

  sentiment_label: 偏空
```

### 5.3 输出结构

```
## 一、当前盘面定位
一句话总结大盘当前状态 + 时间语境 + 核心矛盾。

## 二、指数与结构
主要指数表现 + 谁在护盘/谁在拖累 + 关键支撑/压力。

## 三、板块资金解读
### 资金主攻方向
（净流入居前、抗跌性强的板块 + 资金结构分析）
### 资金撤退方向
（净流出居前、跌幅大的板块 + 判断是出逃还是调整）
### 权重板块一览
（银行/证券/白酒/半导体/新能源/医药/有色/化工逐一简评）
### 板块联动与分化
（是否有轮动特征、内部是否分化）

## 四、趋势与回顾
### 今日走势回顾
从开盘到当前的分时路径（低开高走/高开低走/单边下行等）
### 与昨日的衔接
趋势延续还是转折
### 量价配合
成交额变化、涨跌家数比、涨跌停结构

## 五、消息催化
### 市场情绪
（新闻蒸馏的 sentiment_label + 关键依据）
### 热点题材
（当日核心题材 + 相关板块 + 催化逻辑）
### 利好/利空梳理
（各板块对应的催化或风险事件）

## 六、后续方向判断
### 核心结论
（明确的 directional 判断 + 置信度 + 主要依据）
### 情景演变
（基准/乐观/悲观三种情景 + 触发条件）
### 关键观察点
（接下来需要盯住的信号）

## 七、风险提示
（判断失效的条件、最大的不确定性）
```

## 六、按需查询（"小金属怎么看"）

在云端运行一个轻量 HTTP 服务（FastAPI / Flask），提供一个接口：

```
POST /api/query
Body: { "query": "小金属怎么看" }
Response: { "report": "..." }
```

流程：
```
接收 "小金属怎么看"
  → 识别板块名 "小金属"
  → 从缓存中提取该板块的：
     - 今日实时数据（涨幅/资金流）
     - V15评分（动力分/dz/分位）
     - 新闻蒸馏命中该板块的内容
  → 调用 DeepSeek 做单板块切片解读
     prompt：输入该板块的全维度数据 + 大盘背景
             输出单板块解读（定位/资金/趋势/预期）
  → 推回企业微信群
```

缓存是现成的（定时任务每次采集都会写入），查询不涉及重新采集，秒级响应。
