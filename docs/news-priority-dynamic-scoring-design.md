# 新闻优先级动态评分 — 设计方案

日期：2026-07-01
影响范围：`v14_news_provider.py` + 自动受益的全套下游

---

## 一、问题

`_calc_priority()` 用静态关键词表逐条给新闻打分，不认识市场语境：

- **行情热**：热点板块的普通新闻被低估（如 AI 火爆时涨停新闻不够分）
- **行情冷**：冷板块的结构性信号被埋没（如医药冷清期的 FDA 突破）
- **关键词盲区**：无关键词命中的新闻永远成不了重点（天花板 45 分）

## 二、改造目标

1. priority 保持 `int 0-100`，接口不变，所有下游零改动
2. 加入 **新闻类型 × 板块热度** 两个动态维度
3. 可选 LLM 二次判定补漏
4. 不改新增任何外部依赖，不改数据流

---

## 三、第一层：规则评分改造

### 3.1 关键词按新闻类型分组

`_calc_priority()` 的输入参数微调：追加 `sector="通用"`（可选参数，默认值兼容旧调用）。

关键词表重组织为类型分组：

| 类型 | 基础分 | 举例关键词 | 含义 |
|------|:------:|-----------|------|
| policy | 25 | 降准/降息/制裁/关税/立案/退市 | 宏观政策、监管司法 |
| fundamental | 18 | 订单/中标/涨价/扩产/创新高/突破/复苏 | 行业基本面变化 |
| risk | 20 | 暴雷/违约/破产/财务造假/处罚/ST | 风险事件、利空 |
| capital | 12 | 减持/回购/涨停/跌停/流入/流出 | 资金面、交易面 |
| heavyweight | 10 | 宁德时代/茅台/英伟达/比亚迪/中芯/腾讯 | 权重股异动 |

**评分规则变化：**

```
现在：     分数 = Σ(关键词分值) + 情绪加成 + 热度加成
改造后：   分数 = 类型基础分 + 多类型协同补贴 + 情绪加成 + 板块热度系数 + 热度加成
```

**多类型协同**：一条新闻命中 1 种类型拿基础分，每多命中一种类型额外 +8 分。例如 "英伟达出口管制升级" 同时命中：
- `policy`(25) → 管制是政策行为
- `fundamental`(18) → 影响行业基本面
- `heavyweight`(10) → 英伟达是权重股
- 协同：25 + 18 + 10 + 8×2 = **69**

这与之前最大的区别是：**一条只有"普通"关键词命中的新闻无需依赖大词也能达到较好分数**。

如果一条新闻没有命中任何关键词表中的词 → 0 类型分（规则不变，走情绪+热度通路）。

### 3.2 板块热度系数

**注意**：当前代码中 `_calc_priority()` 是在新闻遍历创建时逐条调用的（line 304），无法预知全批次数据。需要用两趟法：

```
Pass 1: 遍历原始数据，创建 MarketNews 对象（priority 暂用基础分）
Pass 2: 扫描全部已创建新闻，按板块聚合计算板块热度
Pass 3: 遍历新闻，用板块热度系数调整 priority = 基础分 × 系数
```

板块热度算法：
```
板块热度 = Σ(该板块新闻情绪的绝对值 × 标题长度权重) 
热板块取中位数以上的，给予 ×1.2 系数
冷板块取中位数以下的，给予 ×0.85 系数
中性板块 ×1.0
```

> 如果 sector_power 的 T1 缓存可用，可作为板块热度的外部参考，但不作为评分依赖。

这样不需要外部数据源，每次刷新新闻雷达自动计算。

> 如果 sector_power 的 T1 数据已缓存，可下次刷新时作为参考显示在雷达底部，但不作为评分依赖。

## 四、第二层：LLM 二次判定（可选）

### 4.1 灰色地带处理

只在规则分 30-54 的区间使用，区分"确实不重要"和"规则算漏的重要新闻"。

```python
def _llm_judge_priority(candidates: list[NewsItem]) -> list[int]:
    """对规则分 30-54 的新闻做二次判定，返回调整后的分数。
    
    输入：5-10 条模糊新闻标题 + 所属板块
    输出：判定结果，每条返回 55（提升为重点）或 原分不变
    """
```

Prompt 设计：
```
你是A股市场新闻编辑。以下新闻规则评分在灰色地带（30-54分），
请根据你对该新闻是否可能引发板块/市场波动的判断，决定是否提升为"重点新闻"。
背景：今天热点板块为 [{hot_sectors}]。

新闻列表：
1. [AI算力] 某公司xxx...
2. [医药] 某公司xxx...

对每条仅回复 编号:YES 或 编号:NO。
YES=应该重点关注的新闻，NO=确实不重要。
```

**成本**：日均 50-150 条新闻中，约 15-30 条落在灰色地带。一次 LLM 调用可处理全部，约 800-1500 tokens。按 DeepSeek 价格几乎可忽略。

## 六、影响验证

关键发现：当前关键词表本身不包含"政策部署""稳经济""回暖""产能"等词。类型分组能改善的是"命中多种关键词"和"热点板块加权"，但 **完全不命中关键词的新闻第一层仍拿不到高分**。这是类型分组无法解决的——除非扩充关键词表。

估算对比（假设关键词表同步补了几条常见遗漏词：

| 新闻标题 | 旧分 | 新分（估算） | 变化原因 |
|----------|:---:|:------------:|---------|
| "国务院部署稳经济一揽子措施" | 27 | 25(policy) + 12 + ×1.0 = **37** | 若补"经济"入policy则更高 |
| "某AI龙头订单大幅增长" | 32 | 18(fund) + 10(hw) ×1.2(热板块) + 12 = **42** | 板块加权加分 |
| "台积电法说会释放行业回暖信号" | 27 | 18(fund) + 12 ×1.2 = **36** | 板块加权，若补"台积电"入hw更高 |
| "医药公司获FDA突破性疗法认定" | 27 | 18(fund) + 12 ×0.85 = **26** | 冷板块略降，但 LLM 第二层可提到 **55** |
| "政策面+AI龙头双重利好" | 39 | 25+18+8(协同) ×1.2 +12 = **65** | 类型协同生效 |

核心改进：
1. 多条新闻因 **板块热度系数**（×1.2）突破 50 门槛
2. 复合型新闻因 **多类型协同** 显著提分
3. 即使第一层没过 50 的，LLM 第二层可补漏





医药那条即使冷板块也能拿到 26+LLM 补漏 → 55（可选第二层）。核心改进是 **多类型协同** 让复合型新闻升上去，**板块热度系数** 让热点板块新闻更有机会成为重点。

## 七、风险控制

1. **接口不变**：`_calc_priority(title, sentiment, heat, sector="通用")` — 返回 int 0-100，旧调用方自动兼容
2. **数值分布**：新规则可能让平均分提升 5-10 分，但阈值（50/40/30）本身是经验值，可以容忍
3. **冷板块不过度调低**：系数 0.85 降幅有限，真正重要的新闻不会因此被封杀
4. **LLM 二次判定不影响规则分**：它是"提升"通路，不是"降级"通路，不会把该打的新闻打掉
